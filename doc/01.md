# SvelteKit 解説

## SvelteKit のファイル命名規則

SvelteKit では、`src/routes/`ディレクトリ内のファイル名に特別な意味があります。`+`プレフィックスを持つファイルは、ルーティングシステムで特別な役割を持ちます。

### 主要なファイル命名規則

| ファイル名                  | 役割                     | 説明                                              |
| --------------------------- | ------------------------ | ------------------------------------------------- |
| `+page.svelte`              | **ページコンポーネント** | ブラウザで表示される UI コンポーネント            |
| `+page.ts` / `+page.js`     | ページのデータ読み込み   | サーバー/クライアントでデータを取得する関数を定義 |
| `+server.ts` / `+server.js` | **API エンドポイント**   | GET/POST/PUT/DELETE などの HTTP リクエストを処理  |
| `+layout.svelte`            | レイアウトコンポーネント | 複数ページで共通の UI（ヘッダー、フッターなど）   |
| `+error.svelte`             | エラーページ             | エラー発生時の表示を定義                          |

### ファイルベースルーティングの例

```
src/routes/
├── +page.svelte              → https://example.com/
├── about/
│   └── +page.svelte          → https://example.com/about
├── api/
│   ├── calendar/
│   │   └── +server.ts        → https://example.com/api/calendar (APIエンドポイント)
│   └── sync/
│       └── +server.ts        → https://example.com/api/sync (APIエンドポイント)
└── blog/
    ├── +page.svelte          → https://example.com/blog
    └── [slug]/
        └── +page.svelte      → https://example.com/blog/article-name (動的ルート)
```

### なぜ`+`プレフィックスが必要なのか？

SvelteKit は**ファイルベースルーティング**を採用していますが、`+`プレフィックスをつけることで以下のメリットがあります：

1. **特別なファイルであることが一目で分かる**
   - ルーティング対象のファイルと通常のコンポーネントを明確に区別
2. **通常のコンポーネントファイルと混在しても問題ない**
   - `MyComponent.svelte`（普通のコンポーネント）
   - `+page.svelte`（ルーティング対象のページ）
3. **将来的な拡張に対応**
   - SvelteKit 独自の特別なファイルを追加する際に命名の衝突を防ぐ

## 本プロジェクトでの使用例

### ページコンポーネント

- `src/routes/+page.svelte` → メインページ（`/`）
  - タスク管理画面を表示

### API エンドポイント

- `src/routes/api/calendar/+server.ts` → カレンダー API（`/api/calendar`）

  - iCloud CalDAV からイベントを取得
  - GET リクエストでイベント一覧を返す

- `src/routes/api/sync/+server.ts` → KV 同期 API（`/api/sync`）
  - GET リクエスト: Cloudflare KV からデータを読み込み
  - POST リクエスト: Cloudflare KV にデータを保存

## 動的ルートの例

SvelteKit では、`[パラメータ名]`の形式で動的ルートを作成できます：

```
src/routes/
└── blog/
    └── [slug]/
        └── +page.svelte  → /blog/hello-world, /blog/svelte-tutorial など
```

`+page.svelte`内でパラメータを取得：

```typescript
<script lang="ts">
  import { page } from '$app/stores';

  // URL パラメータを取得
  $: slug = $page.params.slug;  // "hello-world"
</script>

<h1>{slug}</h1>
```

## まとめ

- `+page.svelte` = ページ（ブラウザに表示）
- `+server.ts` = API（データを返す）
- `+`プレフィックス = SvelteKit の特別なファイル
- ファイル構造 = URL のルート構造

SvelteKit のルーティングは、**ファイルの配置がそのまま URL になる**シンプルな設計です。
