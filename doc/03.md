# SvelteKit の魔法的な規約

SvelteKit には多くの「規約による設定（Convention over Configuration）」があります。ファイル名やディレクトリ構造によって自動的に機能が有効化される「魔法」のような仕組みです。

## 1. ファイル名の魔法

### 基本的な特殊ファイル

| ファイル名          | 役割                                              |
| ------------------- | ------------------------------------------------- |
| `+page.svelte`      | ページコンポーネント（そのルートの UI）           |
| `+page.ts`          | ページデータローダー（クライアント/サーバー両方） |
| `+page.server.ts`   | サーバー専用データローダー                        |
| `+layout.svelte`    | レイアウトコンポーネント（全ページ共通）          |
| `+layout.ts`        | レイアウトデータローダー                          |
| `+layout.server.ts` | サーバー専用レイアウトローダー                    |
| `+error.svelte`     | エラーページ                                      |
| `+server.ts`        | API エンドポイント                                |

### 例：基本的なページ構成

```
src/routes/
├── +page.svelte              # トップページ（/）
├── +layout.svelte            # 全ページ共通レイアウト
├── about/
│   └── +page.svelte          # /about ページ
└── api/
    └── calendar/
        └── +server.ts        # /api/calendar エンドポイント
```

## 2. 動的ルーティングの魔法

### パラメータ付きルート

```
src/routes/
├── blog/
│   └── [slug]/
│       └── +page.svelte      # /blog/hello, /blog/world など
├── users/
│   └── [id]/
│       └── +page.svelte      # /users/123, /users/456 など
└── docs/
    └── [...path]/
        └── +page.svelte      # /docs/a/b/c などすべてにマッチ
```

### パラメータの取得方法

#### 同期的な例

```typescript
// +page.ts
export function load({ params }) {
  return {
    slug: params.slug, // [slug] から取得
    id: params.id, // [id] から取得
  };
}

// +page.svelte
<script lang='ts'>
  let {data} = $props(); console.log(data.slug); // パラメータを使用
</script>;
```

#### 非同期な例（async/await）

```typescript
// src/routes/blog/[slug]/+page.ts
export async function load({ params, fetch }) {
  // 非同期でデータを取得
  const response = await fetch(`/api/posts/${params.slug}`);
  const post = await response.json();

  return {
    slug: params.slug,
    post: post,
    title: post.title,
    content: post.content,
  };
}

// src/routes/blog/[slug]/+page.svelte
<script lang="ts">
  let { data } = $props();
  // data.post, data.title などが使える
</script>

<h1>{data.title}</h1>
<div>{@html data.content}</div>
```

#### 複数の非同期処理を並列実行

```typescript
// src/routes/user/[id]/+page.ts
export async function load({ params, fetch }) {
  // Promise.all で並列実行
  const [userRes, postsRes, commentsRes] = await Promise.all([
    fetch(`/api/users/${params.id}`),
    fetch(`/api/users/${params.id}/posts`),
    fetch(`/api/users/${params.id}/comments`),
  ]);

  const [user, posts, comments] = await Promise.all([
    userRes.json(),
    postsRes.json(),
    commentsRes.json(),
  ]);

  return { user, posts, comments };
}

// +page.svelte
<script lang="ts">
  let { data } = $props();
</script>

<h1>{data.user.name}</h1>
<p>投稿数: {data.posts.length}</p>
<p>コメント数: {data.comments.length}</p>
```

#### エラーハンドリング付きの非同期例

```typescript
// src/routes/blog/[slug]/+page.ts
import { error } from '@sveltejs/kit';

export async function load({ params, fetch }) {
  const response = await fetch(`/api/posts/${params.slug}`);

  if (!response.ok) {
    // 404 エラーを投げる
    throw error(404, {
      message: '記事が見つかりません',
    });
  }

  const post = await response.json();

  return { post };
}
```

**重要：** `throw error()` すると、通常の `+page.svelte` はレンダリングされず、代わりに `+error.svelte` が表示されます。

#### エラーページの作成

```typescript
// src/routes/blog/[slug]/+error.svelte（このルート専用）
<script lang="ts">
  import { page } from '$app/stores';
</script>

<h1>{$page.status}: {$page.error?.message}</h1>
<a href="/blog">ブログ一覧に戻る</a>
```

```typescript
// src/routes/+error.svelte（全体のフォールバック）
<script lang="ts">
  import { page } from '$app/stores';
</script>

<div class="error-page">
  <h1>エラーが発生しました</h1>
  <p>ステータスコード: {$page.status}</p>
  <p>{$page.error?.message || '予期しないエラーが発生しました'}</p>
  <a href="/">トップページに戻る</a>
</div>
```

**エラーページの優先順位：**

1. 最も近い `+error.svelte`（同じディレクトリ）
2. 親ディレクトリの `+error.svelte`
3. ルートの `src/routes/+error.svelte`（最終フォールバック）

### オプショナルパラメータ

```
[[lang]]/about/+page.svelte
```

- `/about` → マッチ（lang なし）
- `/en/about` → マッチ（lang = 'en'）
- `/ja/about` → マッチ（lang = 'ja'）

### Rest パラメータ

```
[...path]/+page.svelte
```

- `/foo` → path = 'foo'
- `/foo/bar` → path = 'foo/bar'
- `/foo/bar/baz` → path = 'foo/bar/baz'

## 3. グループルートの魔法

URL に影響を与えずにファイルを整理できます。

```
src/routes/
├── (marketing)/          # URL には含まれない
│   ├── +layout.svelte    # マーケティングページ共通レイアウト
│   ├── about/
│   │   └── +page.svelte  # URL: /about
│   └── pricing/
│       └── +page.svelte  # URL: /pricing
└── (app)/                # URL には含まれない
    ├── +layout.svelte    # アプリページ共通レイアウト
    ├── dashboard/
    │   └── +page.svelte  # URL: /dashboard
    └── settings/
        └── +page.svelte  # URL: /settings
```

**メリット：**

- レイアウトやロジックをグループごとに分離
- URL 構造には影響しない
- 認証状態など、異なる要件を持つページを整理しやすい

## 4. データローディングの魔法

### load 関数の戻り値が自動で props に

```typescript
// src/routes/blog/[slug]/+page.ts
export async function load({ params, fetch }) {
  const response = await fetch(`/api/posts/${params.slug}`);
  const post = await response.json();

  return {
    title: post.title,
    content: post.content,
    author: post.author
  };
}

// src/routes/blog/[slug]/+page.svelte
<script lang="ts">
  // load() の戻り値が自動で data に入る
  let { data } = $props();
</script>

<h1>{data.title}</h1>
<p>by {data.author}</p>
<div>{@html data.content}</div>
```

### サーバー専用データ（環境変数、DB 接続など）

```typescript
// +page.server.ts（サーバーでのみ実行）
import { db } from '$lib/server/database';

export async function load() {
  const users = await db.user.findMany();
  return { users };
}
```

**重要：** `.server.ts` のコードはクライアントに送信されない（秘密情報を安全に扱える）

## 5. Form Actions の魔法

フォーム送信を簡単に処理できます。

```typescript
// src/routes/login/+page.server.ts
export const actions = {
  default: async ({ request }) => {
    const data = await request.formData();
    const email = data.get('email');
    const password = data.get('password');

    // ログイン処理
    const user = await authenticate(email, password);

    return { success: true, user };
  }
};

// src/routes/login/+page.svelte
<script lang="ts">
  import { enhance } from '$app/forms';
</script>

<form method="POST" use:enhance>
  <input name="email" type="email" />
  <input name="password" type="password" />
  <button>ログイン</button>
</form>
```

### 名前付きアクション

```typescript
// +page.server.ts
export const actions = {
  login: async ({ request }) => { /* ... */ },
  register: async ({ request }) => { /* ... */ },
  logout: async () => { /* ... */ }
};

// +page.svelte
<form method="POST" action="?/login">...</form>
<form method="POST" action="?/register">...</form>
<form method="POST" action="?/logout">...</form>
```

## 6. ナビゲーションの魔法

### 自動 SPA ルーティング

```html
<!-- 通常の <a> タグだが、SvelteKit が自動的にインターセプト -->
<a href="/about">About</a>
<a href="/blog/hello">ブログ記事</a>

<!-- 外部リンクは通常通り動作 -->
<a href="https://example.com">外部サイト</a>
```

**自動で行われること：**

- ページ遷移時にブラウザリロードなし
- 必要なデータのみを取得
- スクロール位置の復元
- プログレスバー表示（オプション）

### プログラムによる遷移

```typescript
import { goto } from '$app/navigation';

function handleClick() {
  goto('/dashboard');
}
```

## 7. 特殊な Store の魔法

SvelteKit が自動で提供する store：

```typescript
import { page } from '$app/stores';
import { navigating } from '$app/stores';
import { updated } from '$app/stores';

// $page: 現在のページ情報
$page.url; // URL オブジェクト
$page.params; // ルートパラメータ
$page.route.id; // ルートID
$page.status; // ステータスコード
$page.error; // エラー情報
$page.data; // load() の戻り値
$page.form; // form action の戻り値

// $navigating: ナビゲーション中かどうか
if ($navigating) {
  console.log('ページ遷移中...');
}

// $updated: アプリの新バージョンが利用可能かどうか
if ($updated) {
  console.log('新しいバージョンがあります');
}
```

## 8. プリフェッチの魔法

ユーザーがリンクをクリックする前にデータを取得：

```html
<!-- ホバー時にプリフェッチ -->
<a href="/slow" data-sveltekit-preload-data="hover"> 遅いページ </a>

<!-- タップ時にプリフェッチ -->
<a href="/page" data-sveltekit-preload-data="tap"> ページ </a>

<!-- 即座にプリフェッチ -->
<a href="/important" data-sveltekit-preload-data> 重要なページ </a>

<!-- コード分割されたJSも一緒にプリフェッチ -->
<a href="/heavy" data-sveltekit-preload-code="hover"> 重いページ </a>
```

## 9. SSR/CSR 制御の魔法

`+page.ts` または `+layout.ts` で設定可能です。

```typescript
// +page.ts（そのページのみに適用）
export const ssr = false; // SSR 無効化（CSR のみ）
export const csr = true; // CSR 有効化（デフォルト）
export const prerender = true; // 静的生成（ビルド時にレンダリング）
export const trailingSlash = 'always'; // URL の末尾スラッシュ制御
```

```typescript
// +layout.ts（そのレイアウト配下の全ページに適用）
export const ssr = false; // 配下の全ページで SSR 無効化
export const prerender = true; // 配下の全ページを静的生成
```

### 使用例

#### ページ単位で制御

```typescript
// src/routes/dashboard/+page.ts
export const ssr = false; // このページのみ CSR
```

#### レイアウト単位で制御（複数ページをまとめて設定）

```
src/routes/
├── (app)/
│   ├── +layout.ts        # export const ssr = false
│   ├── dashboard/
│   │   └── +page.svelte  # CSR（レイアウト設定を継承）
│   └── settings/
│       └── +page.svelte  # CSR（レイアウト設定を継承）
└── about/
    └── +page.svelte      # SSR（デフォルト）
```

```typescript
// src/routes/(app)/+layout.ts
export const ssr = false; // 管理画面全体を CSR にする
```

### LocalStorage を使う場合

```typescript
// +page.ts または +layout.ts
export const ssr = false; // サーバーでは LocalStorage 使えないので無効化
```

**メリット：**

- `+layout.ts` で設定すれば、配下の全ページにまとめて適用できる
- グループルート `(app)/` などと組み合わせて、管理画面全体を CSR にするなど柔軟に制御可能

## 11. 環境変数の魔法

```typescript
// 環境変数へのアクセス
import { env } from '$env/dynamic/private'; // サーバーのみ（秘密情報）
import { env } from '$env/dynamic/public'; // クライアントも利用可能
import { PUBLIC_API_URL } from '$env/static/public'; // 静的環境変数（ビルド時）

console.log(env.DATABASE_URL); // サーバーのみ
console.log(PUBLIC_API_URL); // どこでも使える
```

**規約：**

- `PUBLIC_` で始まる環境変数 → クライアントでも利用可能
- それ以外 → サーバー専用

## 12. Hooks の魔法

アプリケーション全体に影響する処理を定義：

```typescript
// src/hooks.server.ts
export async function handle({ event, resolve }) {
  // すべてのリクエストで実行される
  console.log(`${event.request.method} ${event.url.pathname}`);

  // 認証チェック
  const session = await getSession(event.cookies);
  event.locals.user = session?.user;

  const response = await resolve(event);
  return response;
}

export async function handleError({ error, event }) {
  // エラーハンドリング
  console.error(error);
  return {
    message: 'エラーが発生しました',
  };
}
```

```typescript
// src/hooks.client.ts
export async function handleError({ error, event }) {
  // クライアントサイドのエラーハンドリング
  console.error('Client error:', error);
}
```

## このプロジェクトで使っている魔法

✅ **ファイルベースルーティング**

- `/api/calendar/+server.ts` → `/api/calendar` エンドポイント
- `/api/sync/+server.ts` → `/api/sync` エンドポイント

✅ **$lib エイリアス**

- `$lib/components/TodoPanel.svelte`
- `$lib/stores/useTodos.ts`
- `$lib/types.ts`

✅ **環境変数**

- `ICAL_USERNAME`, `ICAL_PASSWORD` など（サーバー専用）

✅ **SSR 制御**

- LocalStorage 使用のため、実質的に CSR として動作
- 明示的に `export const ssr = false` を書くと更に明確

✅ **Svelte 5 の新機能（魔法的な $ プレフィックス）**

- `$props()` - コンポーネントの props を取得
- `$state()` - リアクティブな状態
- `$derived()` - 派生状態
- `$effect()` - 副作用（旧 onMount, $: に代わる）

## まとめ

SvelteKit の「魔法」は、以下の原則に基づいています：

1. **ファイル名で機能が決まる** - `+page.svelte`, `+server.ts` など
2. **ディレクトリ構造がルーティングになる** - `src/routes/about/+page.svelte` → `/about`
3. **規約に従えば自動で最適化される** - コード分割、プリフェッチ、SSR など
4. **必要に応じてオプトアウトできる** - `export const ssr = false` など

慣れると非常に生産性が高いですが、最初は「なぜこれが動くのか？」と戸惑うことも多いです。公式ドキュメントを参照しながら、規約を理解していくことが重要です。
